1.1 خلفية المشروع والدافع الهندسي (Motivation & Background):

يشهد قطاع العدالة والمحاماة في مصر والمنطقة العربية فجوة تقنية هائلة في معالجة وحوسبة الوقائع القانونية. تستهلك مكاتب المحاماة آلاف الساعات سنوياً في البحث اليدوي ضمن آلاف المواد القانونية وسوابق محكمة النقض، وتفريغ الوقائع، وحساب التعويضات، في ظل غياب منصة سحابية مؤصلة بالتشريع الوطني.

❌ 1.2 المشكلات الهندسية (Engineering Problem Statement):

• ظاهرة الهلوسة القانونية (Legal Hallucination): عجز نماذج الـ LLM العامة عن الاستشهاد الدقيق بأرقام المواد ومحاكم النقض.
• حاجز اللهجة والمصطلحات الدارجة (Dialectal Gap): عجز الأنظمة عن فهم العامية المصرية ومطابقتها بالتكييف الجنائي والمدني.
• تشتت إدارة المستندات: غياب بيئة عزل آمنة لحوافظ المستندات (PDF / Word / Excel) ومواعيد الجلسات.

✅ 1.3 الحلول المبتكرة في حكمدار (Novel Contributions):

✓ هندسة RAG سيادية مزدوجة: استرجاع دلالي فوري من قاعدة بيانات تشريعية تضم 20 تخصصاً مصرياً.
✓ خوارزمية تطبيع لغوي $O(N)$: تسامح كامل مع الأخطاء الإملائية وتوحيد الهمزات والتاء المربوطة.
✓ وكيل استخراج القضايا (Agentic Dossier Extraction): تحويل الحوار إلى ملف قضية رسمي بضغطة زر.

1.4 الأهداف الهندسية والبحثية للمشروع (Project Objectives):

1. زمن استجابة فائق: تقليل وقت الاستشارة من أيام إلى ثوانٍ معدودة عبر البث الحي (Streaming < 1.2s).
2. دقة تأصيل 100%: ربط الاستشارات بمواد القوانين المصرية وأرقام الدوائر القضائية.
3. عزل وأمان صارم: تطبيق سياسات RLS والتشفير لعزل بيانات موكلي كل مكتب محاماة.

خوارزميات المعالجة الصرفية، البث اللحظي، ومطابقة التخصصات

5.1 خوارزمية التطبيع اللغوي للهجة العربية (Arabic Phonetic Normalizer):

تم تطوير خوارزمية عالية الكفاءة (Linear Time Complexity $O(N)$) تعمل على تنقية وتوحيد الحروف العربية قبل عمليات البحث والاسترجاع، لضمان العثور على النتائج بغض النظر عن طريقة الكتابة:

export function normalizeArabicText(text: string): string { if (!text) return ''; return text.trim().toLowerCase() .replace(/[أإآٱ]/g, 'ا') // Unify all Alef forms .replace(/ة/g, 'ه') // Unify Taa Marbouta with Haa .replace(/ى/g, 'ي') // Unify Alef Maqsoura with Yaa .replace(/[ً-ٰٟـ]/g, ''); // Strip Tashkeel & Tatweel }

5.2 محرك البث الحي عبر SSE (Streaming API):

استخدام generateContentStream لضخ الإجابات كحروف متدفقة عبر ReadableStream، مما يمنح تجربة تفاعلية حية بدون أي انتظار للردود الطويلة.

5.3 الفلترة المتعددة (Multi-Select Tags):

مكونات تفاعلية تسمح باختيار عدة تخصصات (جنائي + عمالي) وعدة محافظات (القاهرة + الجيزة) مع إمكانية الحذف الفوري للبطاقات وتحديد الكل بضغطة زر.

5.4 معالجة تعارض الـ Hydration في React 19 / Next.js 15:

تم حل تعارض الـ SSR بربط بوابات الموكل والمحامي بـ pathname.startsWith('/lawyer') لضمان تطابق الشجرة البرمجية في الخادم والمتصفح بنسبة 100%.
