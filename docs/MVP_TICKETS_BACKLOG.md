# 🤖 المسار الأول: تذاكر فريق الذكاء الاصطناعي (AI & Legal RAG)

---

### 🎫 TICKET-AI-01: بناء محرك التدفق اللحظي للاستشارات القانونية (Legal AI Streaming Engine)
* **المسؤول:** مهندس الذكاء الاصطناعي (AI Engineer)
* **النوع:** Feature / Performance
* **الأولوية:** 🔴 حرجة جداً (P0)
* **الهدف:** تحويل استجابة الـ AI من نظام JSON البطيء إلى استجابة لحظية (Word-by-word streaming).
* **الوصف التقني:**
  * تعديل المسار `/api/ai/chat` ليعتمد على Server-Sent Events (SSE) أو Vercel AI SDK.
  * ربط الـ System Prompt بموسوعة القوانين والتشريعات المصرية لتفادي الهلوسة.
  * استخراج المواد القانونية والملخص كـ Structured Output مفصول عن الرد الحواري.
* **معايير القبول (Acceptance Criteria):**
  - [ ] الرد يبدأ بالظهور للمستخدم في أقل من **800 مللي ثانية**.
  - [ ] في حال انقطاع الاتصال يتم إرسال رسالة خطأ واضحة دون انهيار الصفحة.
  - [ ] عزل الأسئلة غير القانونية برفض مهذب ومنهجي.

### 🎫 TICKET-AI-02: تطوير نظام حراسة النطاق القانوني المصري (Egyptian Legal Guardrails)
* **المسؤول:** مهندس الـ Prompt & RAG
* **النوع:** Security & Accuracy
* **الأولوية:** 🟡 عالية (P1)
* **الوصف التقني:**
  * استبدال الفلترة اليدوية للـ Regex بنظام تصنيف قانوني (Prompt-based Classifier).
  * تدريب النظام على رفض الاستشارات الطبية أو البرمجية أو العامة، والتركيز الحصري على القانون المصري ومحكمة النقض.
* **معايير القبول:**
  - [ ] رفض الأسئلة الخارجة عن القانون بنسبة دقة 100% وبأسلوب وقور.
  - [ ] دعم المصطلحات العامية المصرية (مثل: "طرد للغصب"، "إيصال أمانة على بياض"، "تمكين من شقة الزوجية") وتكييفها قانونياً.

### 🎫 TICKET-BE-01: إنشاء جداول المحادثات وتفعيل سياسات الأمان (Chat Schema & RLS)
* **المسؤول:** مهندس الباك إند (Backend / Database Engineer)
* **النوع:** Database & Security
* **الأولوية:** 🔴 حرجة جداً (P0)
* **الوصف التقني:**
  * إنشاء ملف Migration جديد في `supabase/migrations`:
    1. جدول `chat_sessions`: (id, user_id, title, category, created_at, updated_at).
    2. جدول `chat_messages`: (id, session_id, user_id, sender, text, citations, case_brief_ready, created_at).
  * تفعيل سياسات Row Level Security (RLS) بحيث لا يمكن لأي مستخدم القراءة أو الكتابة إلا في سجلاته فقط.
* **معايير القبول:**
  - [ ] حماية كاملة للمحادثات ومنع تسريب بيانات الموكلين بين الحسابات.
  - [ ] توفير Endpoints للـ CRUD: (إنشاء جلسة، قراءة الجلسات، جلب رسائل جلسة، حذف جلسة).
